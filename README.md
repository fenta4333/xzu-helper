# 西藏大学学业助手（本地版）

一个**纯静态、可离线**的学业辅助网页，围绕三件事：

1. **课表** —— 把教务系统的课表导入后存在本机，随时看；能导出成单文件离线网页、图片、CSV，手机电脑都能带。
2. **体测** —— 自己输入各项成绩，按《国家学生体质健康标准（2014年修订）》大学组评分表算出标准分、加分、总分和等级，并给出提升建议。
3. **文件中心** —— 把保研推免、评奖评优、学籍管理等文件放进来，支持分类、全文检索和在线预览。

> ⚠️ **这不是西藏大学官方系统**，与学校无任何关联。所有数据只存在你自己浏览器的本地存储里，不上传任何服务器，也不联网。

---

## 怎么打开

**方式一：直接双击**

双击 `index.html` 即可。用 `file://` 打开功能完全正常（不依赖服务器、不依赖网络）。

**方式二：本地小服务器**（推荐，浏览器对 `file://` 的存储限制更严格）

```bash
node tools/serve.mjs          # 默认 8080 端口
node tools/serve.mjs 9000     # 指定端口
# 然后浏览器打开 http://127.0.0.1:8080/
```

## 三个主要功能怎么用

### 一、课表

**导入**（顶部「导入课表」页）有三种方式：

| 方式 | 说明 |
|---|---|
| 粘贴文本 | 从教务系统复制课表，直接贴进去，点「解析预览」。支持 CSV / TSV / 表格式文本，自动识别列名和星期、节次、周次写法 |
| 导入文件 | `.json`（本站导出格式）、`.csv`、`.txt`。**GBK 编码的文件会自动转码**，教务系统导出的中文不会乱码 |
| 载入示例 | 15 门虚构课程，用来先试用界面 |

能识别的周次写法：`1-16周`、`1-16周(单)`、`1-16周(双)`、`1,3,5-9周`。
能识别的节次写法：`1-2节`、`第1,2节`、`3-4`。
时间写法：`4'05"`、`4:05`、`4分05秒`、`245`（秒）都会被识别。

**查看**（「我的课表」页）：周次切换、显示全部周次、隐藏周末、课程清单、周次总览、时间冲突提示。点课程块可以看详情、改课程。

**导出**：

| 格式 | 用途 |
|---|---|
| 离线网页（HTML） | **最推荐**。导出的是一个自带数据和样式的单文件，双击就能在任何浏览器打开，不需要本站、不需要网络。发到手机、发给同学都能直接用 |
| 图片（PNG） | 适合发群、发朋友圈，2 倍高清 |
| CSV | 用 Excel / WPS 打开 |
| JSON | 备份或换设备迁移 |
| 打印 | 直接打印或「另存为 PDF」 |

### 二、体测计算

选性别和年级（大一/大二用低年级档，大三/大四用高年级档），填身高体重和各项成绩，点「计算」。

- 身高体重用来算 BMI，BMI 占 **15%** 权重（只分正常/偏低/超重/肥胖四档，分别得 100/80/80/60 分）
- 肺活量 15%、50 米跑 20%、坐位体前屈 10%、立定跳远 10%、引体向上或仰卧起坐 10%、1000 米或 800 米跑 20%
- **加分**：男生引体向上、1000 米跑；女生 1 分钟仰卧起坐、800 米跑。各上限 10 分，合计上限 20 分
- 总分 = 标准分 + 加分，满分 120
- 标准分低于 50 分时，页面会提示毕结业风险

留空的项目不会算成 0 分，而是单独标出「未填写」，并提示补全后总分可能变化。

下拉还有「评分标准」页可以查完整的评分表、权重表、加分表，并能导出 CSV。

### 三、文件中心

- **导入文件**：把 PDF / Word / Excel / 图片拖进来，或点按钮选文件。PDF 和图片能直接在网页里看
- **新建文本**：没有文件时，直接把通知内容敲进去也能用
- **添加链接**：文件太大或者在学校内网，就存个链接
- **搜索**：标题、说明、标签、学院、年份，以及文本类文件**正文全文**都会被搜到
- **分类**：保研推免 / 评奖评优 / 学籍管理 / 教学运行 / 体测体育 / 培养方案 / 办事指南 / 其它
- 导入文件时会**根据文件名自动猜分类**（比如文件名含「推免」就归到保研推免）

> ⚠️ 浏览器本地存储通常只有 5MB 左右。单个文件超过 8MB 或总占用接近上限时，程序**只记录文件目录信息、不保存文件内容**，并在提示里说明。大文件建议保留原文件，或改用「添加链接」。
>
> ⚠️ 程序自带 5 条**占位**文件条目（标注了「占位」标签），内容是虚构的示例，**请替换成教务处发布的真实文件**。本站不提供也不伪造任何学校政策文件。

## 谁能上传文件：管理员与只读发布版

**需求是「普通用户不能上传，只有管理员能上传」。这里必须把话说清楚。**

本站是纯静态网页，没有服务器。这意味着：

| 做得到的 | 做不到的 |
|---|---|
| 普通用户界面上完全看不到上传/编辑/删除入口 | 挡不住懂技术的人打开 DevTools 改内存里的判断 |
| 数据写入函数有运行时守卫，误调用也写不进去 | 挡不住直接改本地文件、改 localStorage |
| 密码加盐 SHA-256 保存，带失败锁定 | —— |
| **打包发布时物理删除全部上传代码** | —— |

> **一句话**：在网页里做密码校验，能挡住「随手点错」和「普通同学」，挡不住「会按 F12 的人」。
> 要真正做到不可绕过，必须有服务端鉴权 —— 静态站点从原理上做不到。

### 解决办法：发布时把上传功能整个删掉

不要直接把源码目录发给同学。用打包工具生成发布版：

```bash
# 硬只读版：物理删除管理员模块，发布版里根本没有上传功能
node tools/pack.mjs --mode=hard

# 同时把整理好的文件烧进去（同学打开就能看，不用自己导入）
node tools/pack.mjs --mode=hard --docs=文件数据包.json
```

打包后生成 `dist/` 目录，把它整个拷给同学即可。**硬只读版做的是物理删除**：

- 删除 `js/modules/auth.js`、`js/modules/auth-view.js`、`js/core/sha256.js`
- 删除文件中心的上传/新建/导出按钮、顶栏管理员入口、设置页的权限与发布卡片
- 移除相关的 `addEventListener` 绑定（否则会因为元素不存在而报错，整个页面打不开）
- 顶部显示只读提示条

打包脚本会自动**校验**：检查发布版里不含 `doc-add-file`、`auth-btn` 等上传相关代码，
并交叉检查 JS 里引用的元素是否都存在于 HTML。校验不通过直接报错退出。

发布版的行为已经用真实 DOM 环境逐条验证过（`tools/test-readonly.mjs`，46 项断言）：
界面无上传入口、无权限模块、绕过界面直接调用写入函数也会被拒绝。

### 管理员怎么维护文件

在**自己这台设备**上打开源码版（不是发布版）：

1. 第一次打开时，文件中心可以直接导入文件（这是你自己的机器）
2. 到「设置与备份」→「账号安全」，设置管理员密码
3. 设置密码后，其他人打开就只能浏览了；自己要维护时点右上角「🔒 管理员登录」
4. 整理好文件后，在「发布给同学」卡片里点「导出文件数据包」，再用上面的打包命令生成发布版

密码以**加盐 SHA-256** 保存（盐随机生成，每次不同），连续输错 5 次锁定 5 分钟。
「记住我」的有效期是 7 天。

### 四种运行状态

| 状态 | 触发条件 | 能否上传 |
|---|---|---|
| 本机 + 未设密码 | 用 `file://` 双击打开，或 `localhost` | ✅ 可以（这是你自己的机器，否则新用户一个文件都传不进去） |
| 网上 + 未设密码 | 部署到 GitHub Pages 等，且没设密码 | ❌ 自动只读（**安全兜底**，见下） |
| 已设密码 | 登录后 | 仅管理员 |
| 硬只读发布版 | 用 `pack.mjs --mode=hard` 打包 | ❌ 任何人都不行（代码已物理删除） |

**「网上 + 未设密码」这条兜底很重要**：没设密码又把页面挂到公网，
等于谁都能上传、改、删你的文件。所以只要检测到是通过网址（非 `localhost`）访问
且没有密码，就自动切成只读。这样即使你**不小心把源码目录直接传上了 GitHub Pages**，
也不会被人乱改 —— 最坏的结果只是变成只读，而不是被人清空内容。

## 部署到 GitHub Pages

### ⚠️ 先看这一条：不要直接部署源码目录

源码目录（含 `js/modules/auth.js` 等）传上去，虽然有上面那条兜底不会被人乱改，
但发布内容会停留在**打包时的示例数据**，而且 `README.md` 会连带泄露管理流程。
正确做法是部署 `dist/` 产物。

### 方式一：GitHub Actions 自动部署（推荐）

仓库里已经放好了 `.github/workflows/deploy-pages.yml`。

1. 把整个项目推到 GitHub 仓库
2. 到仓库 **Settings → Secrets and variables → Actions**，
   新建 Secret：名字 `ADMIN_PASSWORD`，值填你的管理员密码（**至少 10 位**）
3. 到 **Settings → Pages**，把 Source 选成 **GitHub Actions**
4. push 代码，或到 **Actions** 页手动点一次「Run workflow」

之后每次 push 都会自动：跑全部测试 → 打包 → 发布。
同学访问 `https://你的用户名.github.io/仓库名/` 即可。

**为什么密码走 Secret 而不是写进文件**：只读发布版里的密码哈希是公开的
（见下面「必须知道的局限」）。如果把哈希提交进 git，它就永久留在提交历史里，
以后你换密码，旧哈希照样能被翻出来离线暴破。走 Secret 就不会进仓库。

### 方式二：本地打包后手工上传

```bash
# 1. 先在自己电脑上打开源码版，整理好文件，
#    到「设置与备份」→「发布给同学」→ 导出文件数据包
# 2. 打包（密码用你自己的，至少 10 位）
node tools/pack.mjs --mode=soft \
  --admin-password=你的密码 \
  --docs=文件数据包.json \
  --out=dist
# 3. 把 dist/ 里的内容推到 gh-pages 分支，或用 Pages 的「上传」功能
```

`dist/` 里已经带了 `.nojekyll`，GitHub Pages 会按普通静态站点发布
（不加这个文件，Jekyll 会忽略掉下划线开头的文件并可能改变目录结构）。

### 纯静态托管都通用

本站在任何静态托管上都能跑（GitHub Pages / Gitee Pages / Vercel / Netlify / 对象存储 /
校园网空间），因为它**没有任何后端请求**，所有资源都是相对路径，
放在子目录（`用户名.github.io/仓库名/`）也不会 404。

### 必须知道的局限（关于线上管理员登录）

**你能远程登录维护，但改的内容只有你自己那个浏览器看得到。**

这不是 bug，是纯静态站点的原理限制：没有服务端，就没有地方保存「所有人共享」的数据。
你在线上传的文件存在**你自己浏览器的 localStorage** 里，不会同步给任何同学 ——
同学打开同一个网址，看到的仍然是打包时的内容。

所以线上管理适合的场景是：

- ✅ 登录进去**预览**效果、试排版
- ✅ 临时在**自己电脑上**整理内容
- ❌ 不适合让改动对**所有访客生效**

**要让所有同学看到新内容，只能重新打包并重新部署。** 流程是：

```
本机改内容 → 导出数据包 → 重新 push（Actions 自动打包）
  或 → 本地 node tools/pack.mjs ... → 重新上传 dist/
```

如果你希望「改一次，所有人立刻看到」，那必须有服务端（数据库 + 接口），
这就超出纯静态站点的能力范围了。

### 密码能不能被破解

发布版里的密码是**加盐 SHA-256**，不含明文，但**哈希本身随网站公开**。
懂技术的人可以把它下载下来离线暴力破解。所以：

- 密码**至少 10 位**（打包工具会强制检查，短于 10 位直接报错）
- 建议用一句自己能记住的长口令，例如 `xzu-baoyan-2025-教务处`
- 不要用 `admin123`、`123456`、学号、生日这类

另外请清楚：**这道密码保护挡的是「普通同学随手点一下」，不是「懂技术的人刻意绕过」。**
静态网页的所有判断都在浏览器里，打开 DevTools 就能改。
真正想让任何人都无法上传，用 `--mode=hard` 打包 —— 那个版本的上传代码
是被物理删掉的，不存在可以绕过的判断。

## 数据与备份

所有数据存在浏览器 `localStorage`，键名前缀 `xzu.`：

| 键 | 内容 |
|---|---|
| `xzu.timetable.v1` | 课表 |
| `xzu.fitness-profile.v1` | 体测资料与上次输入 |
| `xzu.docs.v1` | 文件条目（含小文件内容） |
| `xzu.settings.v1` | 设置 |
| `xzu.auth.v1` | 管理员密码（加盐 SHA-256，不含明文） |
| `xzu.auth.session.v1` | 登录会话（仅「记住我」时写入） |

「设置与备份」页可以：

- 导出全部数据为 JSON 备份（**换浏览器、换设备、清理缓存前请务必导出**）
- 从备份恢复
- 清除全部本地数据
- 查看已用空间

⚠️ 清理浏览器数据、用无痕模式、换浏览器都会导致数据丢失。重要数据请定期导出备份。

```bash
npm test                        # 跑全部七套（共 488 项断言）
node tools/test-sha256.mjs      # SHA-256 实现正确性（43 项）

node tools/test-source-load.mjs # 源码版加载检查（18 项，需要 jsdom）
node tools/test-readonly.mjs    # 只读发布版验收（46 项，需要先打包）
npm run test:readonly           # 先打包再验收，一条命令跑完
node tools/test-deploy.mjs      # 部署到 GitHub Pages 的场景验收（33 项）
```

**SHA-256 测试**的写法值得说一下：密码哈希用的是自己实现的纯 JS SHA-256
（浏览器在 `file://` 下取不到 `crypto.subtle`），密码学原语不能靠「看起来对」，
所以这 43 项断言是**直接跟 Node 的 `crypto` 逐字节比对**的 —— 标准向量、
块填充边界长度（55/56/57/63/64/65）、中文与 emoji 代理对、200 组随机字符串对拍。

**DOM 集成测试**会真的加载 `index.html` 和全部脚本，模拟点击、输入、导入、导出、
备份恢复、清空数据等完整流程，导出的离线 HTML 也会被真的打开跑一遍，确认能独立工作。
其中的权限部分覆盖：未设密码 / 设密码 / 登录失败 / 连续失败锁定 /
普通访客看不到也调不动上传 / 管理员正常增删改 / 只读模式 / 改密码 / 取消密码保护。

**只读发布版验收测试**不信任打包脚本自己的说法，而是把 `dist/` 真的加载进 DOM，
从外部模拟一个普通访问者，逐条确认：全局没有 `Auth` 对象、HTML 里没有上传按钮、
JS 里没有 admin-only 区块、绕过界面直接调用 `importFiles` 和写入函数也会被拒绝、
发布内容不会落进访客的 localStorage，同时课表/体测/标准查询/文件浏览全部正常可用。

首次运行 DOM 测试需要装 jsdom：

```bash
npm install
```
